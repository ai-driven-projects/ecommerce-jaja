# Contexto do projeto (ler antes de executar)

- Namespace do monorepo: `@jaja`. Pacote de domínio: `modules/catalog` (`@jaja/catalog`). Shared: `@mentoria-360/shared` (submódulo em `packages/shared`). Skills em `.claude/skills/*`; padrão de nomes em `.claude/skills/skills-standards.md` (pastas `model/`, `provider/`, `use-case/`, `dto/`; sufixos `.entity.ts`, `.repository.ts`, `.query.ts`, `.use-case.ts`, `.vo.ts`).
- VOs disponíveis no shared: `Id`, `Name` (2–100 caracteres), `Alias` (slug `^[a-z0-9]+(?:-[a-z0-9]+)*$`, com `Alias.format(texto)` para gerar slug a partir de um nome), `Text` (com `minLength`/`maxLength`), `Url` (apenas http/https), `Flag` (booleano). Entidades estendem `Entity` do shared, que já fornece `id`, `createdAt`, `updatedAt`, `deletedAt` e `cloneWith`. `CrudRepository<T>` do shared define `create(entity, tx?)`, `update(entity, tx?)`, `findById(id): Promise<Result<T>>` e `delete(id, tx?)`. Validação com `Result.combine`, expondo `create`/`tryCreate` e getters.
- `modules/catalog` hoje contém apenas o scaffold placeholder `src/catalog` (entidade `Catalog`, `CreateCatalog`, `CatalogDTO`, repositório, mock in-memory e teste). Ele deve ser removido nesta funcionalidade, mantendo `getModuleName()` e seu teste em `test/index.test.ts`. Os testes do pacote usam jest.
- Backend é ESM (`"type": "module"`): imports relativos com sufixo `.js`. `@jaja/catalog` é consumido via `dist`: rodar `npm run build --workspace=@jaja/catalog` antes de usar no backend. `PrismaService` (`apps/backend/src/db/prisma.service.ts`) implementa `TransactionManager` e exporta `PrismaTransactionContext`; `apps/backend/src/modules/auth/user.prisma.ts` é a referência de adapter Prisma.
- Área administrativa já criada (prompt 06): no backend, `@AdminOnly()` (`apps/backend/src/shared/decorators`) aplica `JwtGuard` + `AdminGuard` (`401` sem token, `403` para não administrador); no frontend, as telas protegidas ficam no grupo `apps/frontend/src/app/admin/(shell)` (que já aplica `AdminGuard` e o shell) e o módulo Catálogo tem no menu (`src/shared/navigation/app-modules.ts`) o sub-item "Visão geral" e a seção vazia "Cadastros" (`id: 'catalog-registrations'`).
- Autenticação já implementada: a flag de administrador se chama `admin` na API e no JWT. No frontend, `useAuth()` (`src/modules/auth/data/auth.context.tsx`) expõe `session` (com `token` e `user`), `user` e `isAdmin`. O cliente HTTP do auth (`src/modules/auth/data/auth.api.ts`) usa `NEXT_PUBLIC_API_URL` e traduz os códigos de erro da API com `describeApiError` + `src/shared/i18n/messages.pt.ts`.
- Frontend em Next.js 16: nas `page.tsx` com segmento dinâmico, `params` é uma `Promise`.
- **Dados de referência:** `apps/cli/data/kalunga/brands.json` (objeto `{ source, scrapedAt, brands }`; `brands` tem 214 marcas raspadas da Kalunga, cada uma com `id` = CNPJ do fornecedor, `name`, `slug`, `url` da página na Kalunga, `products` e `categories`). Há nomes repetidos com ids diferentes e o mesmo slug: `Spiral` (2), `HP`/`Hp` (3) e `Trident` (2); no nosso catálogo cada um vira **uma** marca, o que resulta em **210 marcas**. A marca `Make+` tem o slug inválido `make-` (hífen no fim), que precisa ser normalizado com `Alias.format` (vira `make`). Os dados não trazem logo nem descrição. Não editar esses arquivos.
