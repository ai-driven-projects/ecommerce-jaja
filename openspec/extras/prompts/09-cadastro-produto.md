# Contexto do projeto (ler antes de executar)

- Namespace do monorepo: `@jaja`. Pacote de domínio: `modules/catalog` (`@jaja/catalog`), que já possui os agregados `brand` (prompt 07) e `category` (prompt 08), com repositórios, queries, casos de uso `save-*`/`delete-*`, mocks in-memory e testes. Shared: `@mentoria-360/shared`. Skills em `.claude/skills/*`; padrão de nomes em `.claude/skills/skills-standards.md`.
- VOs disponíveis no shared: `Id`, `Name` (2–100 — **curto demais para nomes de produto**), `Alias`, `Text` (`minLength`/`maxLength`), `Url`, `Flag`, `Order`, `PositiveInteger`, `NonNegative`. VOs específicos do módulo ficam em `modules/catalog/src/product/model/*.vo.ts` (skill: module-value-object).
- Backend é ESM (imports com `.js`). `@jaja/catalog` é consumido via `dist`: rodar `npm run build --workspace=@jaja/catalog` antes de usar no backend. `PrismaService` implementa `TransactionManager`. Endpoints administrativos usam `@AdminOnly()`. Frontend (Next.js 16, `params` é `Promise`): `/admin`, com as telas protegidas no grupo `apps/frontend/src/app/admin/(shell)`; módulo `apps/frontend/src/modules/catalog`; chamadas à API via `apiRequest`/`ApiError` de `src/shared/util/api-client.util.ts`, com o token de `useAuth().session` passado por parâmetro (ver `brand.api.ts` e `category.api.ts`); `formatPrice(cents)` em `src/shared/util/price.util.ts`; componentes `Combobox`, `OrderableObjectList`, `PaginationControls`, `TableCard`, `DeleteConfirmationDialog` em `src/shared/components/ui`. Seção "Cadastros" (`catalog-registrations`) do módulo Catálogo já contém "Marcas" e "Categorias".
- A vitrine pública (`/`) continua usando os mocks de `apps/frontend/src/modules/catalog/data/storefront.mock.ts`. **Integrar a vitrine à API não faz parte desta funcionalidade.**
- **Dados de referência:** `apps/cli/data/kalunga/categories/<slug>.json`, campo `products[]` (1.200 entradas, 1.076 produtos únicos — o mesmo produto aparece em mais de um departamento). Cada produto traz: `id` (código na Kalunga, string), `slug`, `url`, `name` (até 214 caracteres), `brand { id, name, slug, url }`, `category { department, group, subgroup, path }`, `price { current, list, installments { count, amount, total }, currency }` (valores em reais; `list` é o preço "De:", presente em ~9% dos itens), `images [{ thumb, large }]` (sempre ao menos uma), `description { html, text }` (texto até ~4.900 caracteres), `rating { stars, count } | null`, `available` (19 indisponíveis) e `scrapedAt`. Entre os produtos únicos, um par de produtos distintos compartilha o mesmo `slug`, e dois slugs de marca (`dvt-comercio-importa` e `dover`) não existem em `brands.json`. Parcelamento e avaliação **não** entram no cadastro básico (são assunto de pagamento e de avaliações, funcionalidades futuras). Não editar esses arquivos.

- Alterar a entidade `product` para possuir os seguintes atributos:
  - `id` — identificador único (`Id`)
  - `name` — nome do produto (obrigatório, `ProductName`)
  - `slug` — identificador de URL (obrigatório, `Alias`); único no catálogo; derivado do nome quando não informado
  - `sku` — código interno (opcional, texto até 40 caracteres); único quando informado
  - `brandId` — id da marca (opcional, `Id`); produto pode não ter marca
  - `categoryId` — id da categoria (obrigatório, `Id`); pode ser de qualquer nível

  - `unit` — unidade de venda exibida na vitrine (texto até 40 caracteres, padrão `"unidade"`; ex.: `"caixa com 50"`)
  - `images` — lista de `ProductImage` (0 a 10 itens); a de menor `order` é a imagem principal; a entidade normaliza `order` para a sequência 0..n-1
  - `isActive` — indica se o produto está ativo/visível; padrão `true` (`Flag`)
